# Format:  URL   family source type study_only [extra tags]   # what it is [size]

# !! COLLECTOR CAVEAT: ml/collect_refs.py treats each line as ONE recording (`yt-dlp --no-playlist --print id`).
# !! For a playlist / user / set URL that prints many ids, the rid has newlines, so yt-dlp downloads the whole
# !! feed but no manifest rows get written (reported as 'failed'). Either expand these with
# !!   yt-dlp --flat-playlist --print url <URL>
# !! into one line per item first, or teach the collector to iterate playlist entries. Single-video /
# !! single-episode lines (YouTube watch?v=, NTS episodes) work as-is.
# !! Mixcloud from yt-dlp currently needs impersonation (pip install 'yt-dlp[default,curl-cffi]'), else HTTP 403.
